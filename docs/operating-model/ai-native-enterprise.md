# AI-Native Enterprise Operating Model

Dark Factory OS models an enterprise where agents are treated like governed digital workers, not scripts.

## Operating Principles

- Agents have identities, owners, scopes, tools, budgets, and status.
- Tools have risk classes, schemas, auth modes, and test status.
- Skills are versioned, evaluated, and owned by teams.
- Human approvals are part of the architecture, not a fallback modal.
- Memory has trust, access scope, decay, and consistency checks.
- Every material action leaves a trace, audit event, and cost record.

## Personas

| Persona | Needs |
|---|---|
| CFO / finance manager | Policy compliance, spend control, audit trail |
| Commercial manager | Margin, inventory, pricing, promo actions |
| SaaS ops lead | Incident context, customer impact, follow-up automation |
| Operator | Run state, exceptions, approval queue, retry controls |
| Admin / skill publisher | Tool registry, budgets, skill versions, eval gates |

## Adoption Path

1. Start with read-only copilots over trusted synthetic or internal data.
2. Add proposal workflows with ActionReadinessPacks.
3. Gate financial and destructive tools.
4. Add durable jobs for follow-up and scheduled monitoring.
5. Add skill learning loops that propose, evaluate, and review improvements.
6. Promote only workflows with passing evals and operational traces.
